# Changelog

## 0.2.2 — 2026-11-05

- Require an explicit project-readiness check before OpenSpec-dependent work in both new and existing projects; component availability does not establish project initialization.
- Resolve the selected project or linked store, initialize within applicable authorization when needed, and verify generated locations plus a supported project query before creating or resuming a change.
- Preserve linked-store ownership, existing work, and participation boundaries; report blocked setup and explicit OpenSpec non-use in lightweight tasks.
- Validate the changed decisions through six bounded synthetic cases and an actual isolated initialization/query run with the existing OpenSpec 1.15.0 CLI. These checks do not establish live Codex discovery or full upstream workflow compatibility.

## 0.2.0 — 2026-10-30

- Add first-use environment inspection, official-source discovery, scoped authorized setup, layered readiness checks, and return to the original task.
- Add opt-in personalization with required-skill detection, official-source installation offers and authorization, then explicit project/conversation scope and read access before layered actual-use analysis; keep private evidence and personal candidates separate.
- Clarify novice handovers and the difference between an embedded installer and an agent performing authorized setup.
- Extend the deliberate publication set with the two portable reference branches; preserve the skill identifier and independent upstream installations.
- Exercise authorized and declined-helper flows in a stateful synthetic zero-installed-skill host, with explicit real-versus-simulated evidence boundaries.

These are instruction/documentation changes. Package/example checks and bounded simulations do not establish live installation, account-wide history access, universal model compliance, or full upstream compatibility.

## 0.1.0 — 2026-10-30

- Initial public, host-neutral coordination skill for SDD, TDD, DDD, and BDD.
- Explicit artifact ownership and stage handoffs for OpenSpec, Superpowers, and domain-modeling workflows.
- Twenty-six conditional conflict cases with scoped decisions, invalidation, and recovery.
- Participation modes for explanation, guided learning, delivery, and read-only investigation.
- English documentation, Chinese overview, MIT license, and upstream attribution.
- Self-contained loan-renewal example and dependency-free repository validation.

Validation is scoped to package checks and the example. Automatic discovery, universal upstream compatibility, and independent model compliance are not claimed.
